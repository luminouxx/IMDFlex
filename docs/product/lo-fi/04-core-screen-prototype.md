# 핵심 화면 Lo-Fi Prototype

상태: 8개 대표 화면 완성 및 Figma 연결 완료

작성일: 2026-08-20

Figma: [IMDFlex Lo-Fi Prototype](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=13-2)

## 목적

31개 전체 화면을 한 번에 상세화하기 전에, IMDFlex의 가장 중요한 판단과 제작 행동이 실제 iPad 화면 구조 안에서 이해되는지 확인한다. 이 단계에서는 아름다움보다 정보 구조, 맥락 유지, 다음 행동의 명확성, 문제 해결의 닫힌 흐름을 우선한다.

## 선택한 8개 화면

| Screen ID | 화면 | 검증하려는 질문 |
| --- | --- | --- |
| `HOME-01` | 최근 프로젝트 | 사용자가 작업 상태를 비교하고 다시 시작할 프로젝트를 찾을 수 있는가? |
| `EDIT-01` | 프로젝트 개요 | 문제·단계·공간 상태를 함께 이해하고 마지막 작업으로 돌아갈 수 있는가? |
| `EDIT-02` | 편집기 셸 | 현재 건물·층·Feature 단계와 지도 작업 영역을 구분할 수 있는가? |
| `AUTHOR-01` | Feature 선택기 | 검색·최근 사용·추천·전체 계층에서 올바른 Feature를 고를 수 있는가? |
| `AUTHOR-02` | Polygon 그리기 | 점 기반 Geometry 작성, Undo, Draft 보존을 이해할 수 있는가? |
| `AUTHOR-08` | Feature 인스펙터 | 속성, 짧은 설명, 대표 예시, 흔한 실수를 한 맥락에서 확인할 수 있는가? |
| `REVIEW-03` | 문제 상세 | 무엇이 왜 문제이며 지도에서 어디를 수정해야 하는지 알 수 있는가? |
| `EXPORT-02` | 제출 전 검사 | 제출 차단 이유와 개발·검토용 ZIP 허용 정책을 구분할 수 있는가? |

## 대표 Prototype 흐름

```text
HOME-01
→ EDIT-01
→ EDIT-02
→ AUTHOR-01
→ AUTHOR-02
→ AUTHOR-08
→ EXPORT-02
→ REVIEW-03
→ AUTHOR-08
```

이 연결은 31개 전체 Happy Path를 축약한 사용성 테스트용 흐름이다. 작성 완료 후 제출 검사를 실행하고, 차단 문제를 발견하면 문제의 원인과 위치를 확인한 뒤 선택한 Feature의 속성 수정으로 돌아간다.

## 공통 화면 구조

- 대상 크기: iPad 가로 `1194 × 834`
- 상단: 화면 제목과 현재 프로젝트·건물·층·단계 맥락
- 왼쪽: 현재 작업의 범위, 도구, 상태 또는 목록
- 오른쪽: 지도·도면·폼·문제 설명 등 주 작업 영역
- 하단: 현재 화면에서 가장 중요한 Primary Action 하나
- 간격: 4의 배수
- 표현: 회색조와 단순 도형만 사용

이 구조는 최종 디자인 시스템이 아니다. 8개 화면에서 정보의 위치를 학습할 수 있는지 검증하기 위한 임시 Lo-Fi 규칙이다.

## 검증 결과

- 8개 화면이 모두 `1194 × 834` 크기로 존재한다.
- 각 화면에 Primary Action이 하나씩 있으며 다음 대표 화면으로 연결된다.
- Placeholder가 남아 있지 않다.
- 텍스트 잘림, 비정상적으로 좁은 텍스트 박스, 화면 밖 요소가 발견되지 않았다.
- 한글 텍스트는 `Noto Sans KR`로 통일했다.
- 문제 해결은 제출 검사 → 문제 상세 → Feature 수정의 닫힌 Loop를 가진다.

## 현재 범위 밖

이 8개 화면만으로는 새 프로젝트 생성, 주소 검색, Venue·건물·층 설정, 평면도 등록·정렬, 관계 선택, 재검사 진행, ZIP 생성 성공을 직접 테스트할 수 없다. 오류 때문에 제출이 차단되는 기본 상태는 `EXPORT-02`에 포함했지만, 오프라인, 취소 확인, Geometry 완료 차단, 재검사 실패, ZIP 생성 실패와 같은 예외 상호작용은 아직 화면형 Prototype에 포함하지 않았다.
