Status: 완료 · 최종 구조·논리·UI 검증 통과

Figma: [IMDFlex Lo-Fi Prototype](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-2)

## 1. 결론

IMDFlex 전체 IA의 82개 Screen Family를 Figma Lo-Fi로 구현했다. 정상 흐름뿐 아니라 생성 취소, 오프라인, 잘못된 Geometry·관계, 재검사, 제출 차단, ZIP 실패·취소, 도면 교체, 버전 복원, 동기화 충돌까지 별도 상태로 표현했다.

최종 자동 검사에서 93개 상태 화면 모두에 나갈 수 있는 Prototype 경로가 있었고, 목적지 없는 화면은 0개였다. 화면 크기, 글꼴, Placeholder, 화면 경계 이탈도 모두 통과했다.

## 5. 닫힌 핵심 흐름

### 새 프로젝트에서 ZIP까지

```text
최근 프로젝트 → 시작 방식 → 프로젝트 기본 정보
→ 주소·Venue·Building·Level → 평면도 등록·정렬
→ 프로젝트 개요 → 지도 편집 → Feature·관계 작성
→ 문제 확인·수정·재검사 → Preflight → ZIP 생성
→ Apple Validator 안내 → 프로젝트 또는 버전 기록
```

### 문제 해결 반복

```text
문제 목록 → 문제 선택 → 지도 위치와 설명 → 수정 시작
→ Geometry 수정 → 재검사
├─ 해결됨: 성공 배너 + 남은 문제 목록
├─ 같은 문제 존재: 기존 위치·설명 화면
└─ 오류 0: 내보내기 준비
```

해결된 문제는 현재 문제 목록에서 제거하고 성공 배너에서만 보여준다. 목록으로 돌아갈 때 필터, 스크롤, 건물·층 펼침 상태와 정렬을 유지한다.

### 안전한 취소·복구

```text
Drawing Draft 이탈 → 계속 그리기 / 초안 버리기
ZIP 생성 취소 → 확인 → 임시 파일 삭제 → Export Hub
Building·Level 삭제 → 영향 확인 → 복구 버전 생성 → 삭제
버전 복원 → 현재 상태 복구 버전 생성 → 프로젝트 전체 복원
iCloud 충돌 → 두 버전 보존 → 활성 버전 선택
```

## 6. 논리 검증 기준

- 모든 화면은 이전, 취소, 완료, 다음 행동 중 하나 이상으로 나갈 수 있다.
- 오류 화면은 원인, 영향받는 대상, 복구 행동을 제공한다.
- 취소가 데이터 손실을 만들 수 있으면 확인 단계를 둔다.
- 작업을 건너뛰어도 프로젝트 탐색은 가능하며, 필요한 종속 작업만 차단한다.
- 제출 차단형 미완료와 Workflow 경고형 미완료를 구분한다.
- Apple IMDF Validator 통과나 제출 가능성을 앱 내부 검사만으로 보장하지 않는다.
- Figma의 단순 클릭 Prototype에서 자동 데이터 분기는 구현할 수 없으므로 결과별 상태 화면을 명시적인 대안 경로로 표현했다. 이는 Dead point가 아니다.

## 7. UI 전수 검수 기준

- 버튼, 목록, 검색창, Form, 지도, Inspector, 상태 배너를 모양으로 구분할 수 있는가
- 화면 제목과 현재 프로젝트·건물·층 맥락이 보이는가
- Primary와 Secondary 행동의 우선순위가 분명한가
- 지도 위 Polygon, Line, Point, Opening, Vertex가 의미에 맞게 표현되는가
- 선택된 목록·Category·Level·PDF 페이지가 시각적으로 구분되는가
- 텍스트가 잘리거나 화면 밖으로 나가지 않는가
- 모든 배치가 4pt 간격 체계를 따르는가
- 오프라인·동기화·잠금·개인정보 상태에서 가능한 행동이 명확한가
- 외부 Apple Validator 단계와 앱 내부 Preflight를 혼동시키는 문구가 없는가

## 8. UI 검수 중 반영한 수정

- `AUTHOR-06`의 Polygon이 Level 경계를 벗어나 보이지 않도록 Geometry를 수정했다.
- Opening을 의미 없이 돌출된 막대가 아니라 Unit 경계의 출입구로 읽히도록 표현을 수정했다.
- Geometry 수정의 진입, 수정 중, 유효성 통과 상태를 분리했다.
- 재검사 성공 후 해결된 문제는 목록에서 제거하고 성공 배너로 이동했다.
- 문제 목록 복귀 시 기존 필터와 스크롤 위치를 유지하도록 흐름을 고정했다.
- 목록, PDF 페이지, Level, Category, 겹친 Feature에 선택 상태를 추가했다.
- 기준점 정렬에서 아직 찍지 않은 세 번째 점을 점선 상태로 구분했다.
- 내보내기 성공 화면의 과도한 제출 보장 문구와 잘린 버튼을 수정했다.

## 9. 승인된 제품 결정

논리적 구멍으로 발견된 10개 항목은 모두 `decision-log.md`의 `D-LF-001`~`D-LF-010`으로 승인·반영했다.

- Draft Project 생성과 폐기
- Drawing Draft 이탈과 복구
- 미완료의 제출 차단 기준
- Setup 단계 Skip
- Building·Level 삭제와 복구
- ZIP 생성 중 취소
- 도면 교체 후 Geometry 유지 방식
- 프로젝트 버전 복원 범위
- iCloud 충돌 보존 방식
- 기존 IMDF Import 보존·경고·거절 정책

## 10. 완료 판정과 다음 단계

Lo-Fi 단계는 완료다. 다음 단계는 새로운 화면을 더 그리는 일이 아니라, 대표 작업을 실제 사용자에게 수행시켜 용어·순서·조작의 이해도를 확인하는 Task-based 사용성 테스트다. 테스트에서 논리 문제가 발견되면 해당 Screen Family와 Decision ID로 되돌아가 수정한다.
