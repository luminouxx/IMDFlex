# 전체 제작 흐름 Lo-Fi Wireflow

상태: 전체 Wireflow 및 82개 Screen Family·예외 상태 연결 완료

작성일: 2026-08-20

## 목적

이 Wireflow는 시각 디자인을 시작하기 전에 IMDFlex의 핵심 제작 과정이 논리적으로 연결되는지 확인하기 위한 것이다. 31개 Ready 화면을 뼈대로 사용하고, 전체 82개 Screen Family와 위험 예외 상태를 확장했다. 모든 화면은 추적 가능한 Screen ID를 유지한다.

## 성공 조건

1. 사용자가 프로젝트가 없는 상태에서 시작해 `imdf.zip` 내보내기까지 도달할 수 있다.
2. 프로젝트, Venue, 건물, 층, 편집 대상의 현재 맥락을 이해할 수 있다.
3. 발견한 오류가 실제 수정과 재검사로 이어지고 곧바로 내보내기로 건너뛰지 않는다.
4. 제출 차단형 미완료와 Workflow 미완료를 구분할 수 있다.
5. 장시간 작업 중 앱을 벗어나도 프로젝트와 Drawing Draft를 잃지 않는다.

## 닫힌 문제 해결 흐름

```text
문제 요약
→ 문제 상세
→ 문제 위치
→ Geometry 선택 및 편집
→ 재검사
→ 재검사 결과
→ 내보내기 허브
→ 제출 전 검사
→ 내보내기 진행
→ 내보내기 성공
→ 최근 프로젝트
```

재검사 결과에 문제가 남아 있으면 방금 해결된 문제를 상단 성공 배너에서 강조하고, 해결된 항목은 현재 문제 목록에서 제거한다. 사용자는 전체 문제 목록에서 다음 문제를 직접 선택한다. 문제를 선택하면 지도 위치와 원인·수정 방법을 먼저 확인하고 `수정 시작`을 눌러 편집한다.

같은 오류가 검사 후에도 존재하면 별도의 실패 화면이나 `다시`, `여전히`, `아직` 문구를 만들지 않는다. 기존 문제 위치·설명 화면을 그대로 사용하고 `검사 완료 · 오류 1개`처럼 현재 결과만 표시한다. 목록으로 돌아갈 때는 이전 스크롤, 필터, 건물·층 펼침 상태와 정렬을 유지한다.

앱 내 오류가 0개인 결과는 `앱 내 사전 검사에서 오류가 발견되지 않았습니다`로 표현한다. Apple IMDF Validator 확인은 내보내기 후 별도 절차이며, 제출 가능성을 보장하는 문구는 사용하지 않는다. 제출 전 검사에서 제출 차단형 미완료가 발견되면 `EXPORT-02`에서 영향받는 Feature로 돌아간다. 개발·검토용 ZIP은 이러한 문제와 관계없이 내보낼 수 있다.

## Lo-Fi 화면 규칙

각 화면에는 다음 정보만 표시한다.

- Screen ID와 화면 제목
- 필요한 경우 현재 프로젝트, 건물, 층 맥락
- 화면의 핵심 목적 한 가지
- 주요 행동 한 가지
- Coverage Matrix가 요구할 때만 Back, Cancel, Skip, Retry
- 다음 Screen ID

시각 규칙은 회색조, 상호작용 강조색 하나, 4의 배수 간격만 사용한다. 이 규칙은 최종 IMDFlex 디자인 시스템이 아니라 논리 검증을 위한 임시 Lo-Fi 규칙이다.

## 위험 상태 확장 결과

다음 위험 분기는 별도 화면 또는 연결 상태로 모두 반영했다.

- Draft Project 취소 및 폐기
- 주소 검색 오프라인·오류
- 그리기 중 층 또는 도구 전환
- 유효하지 않은 Geometry
- 재검사 후 해결되지 않은 문제
- 제출용 내보내기 차단
- ZIP 생성 실패와 재시도
