# IMDFlex Lo-Fi Task-based 사용성 테스트 계획

Status: Agent Pilot Round 1 보정 중 · 사람 대상 테스트 전 재검사 필요

작성일: 2026-08-25

Figma: [IMDFlex Lo-Fi Prototype](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-2)

## 1. 이번 테스트의 목적

이번 테스트는 화면이 예쁜지를 평가하지 않는다. 사용자가 설명 없이도 IMDFlex의 작업 순서와 상태를 이해하고, IMDF 데이터를 안전하게 작성·수정·내보낼 수 있는지를 검증한다.

검증 질문은 다섯 가지다.

1. 사용자가 현재 프로젝트·건물·층·Feature 맥락을 잃지 않는가?
2. 평면도 정렬과 Feature 작성 순서를 스스로 이해하는가?
3. Unit과 Opening의 Geometry·경계 연결 규칙을 이해하는가?
4. 오류의 원인과 위치를 찾고 수정·재검사까지 완료하는가?
5. 앱 내부 Preflight와 Apple IMDF Validator를 구분하는가?

## 2. 참가자

- Round 1 권장 인원: 5명
- 우선 대상: IMDF를 전문적으로 사용하거나 납품 업무를 수행하는 사람
- 허용 대상: IMDF 경험은 있으나 규칙을 매번 기억하지는 못하는 사람
- 제외 대상: 현재 IMDFlex 설계에 직접 참여해 화면 구조를 이미 아는 사람
- 1차 기기: iPad 가로 모드
- 2차 비교: Mac은 iPad에서 발견된 문제를 수정한 후 진행

## 3. 진행 방식

- 방식: 1:1 Moderated Test
- 시간: 첫 Human Pilot 1인당 75분, 안정화 후 본 테스트 60분 목표
- 환경: Figma Prototype, 화면·음성 기록, 관찰자 기록지
- 원칙: 참가자에게 버튼 이름이나 이동 순서를 알려주지 않는다.
- Think Aloud: 무엇을 기대하고 왜 눌렀는지 말하도록 요청한다.
- 힌트: 90초 이상 진행하지 못할 때만 단계적으로 제공한다.

### 세션 구성

| 구간 | 시간 | 내용 |
|---|---:|---|
| 소개·동의 | 5분 | 목적, 녹화, Think Aloud 안내 |
| 사전 질문 | 5분 | IMDF 경험, 기존 도구, 납품 방식 |
| 핵심 과업 | 55분 | T1~T6 수행, T3·T5 하위 과업 포함 |
| 사후 질문 | 10분 | 신뢰, 어려움, 기대와 다른 점 |

## 4. 진행자 시작 문구

> 오늘은 여러분을 평가하는 것이 아니라 제품을 평가합니다. 화면에서 무엇을 기대하는지, 왜 특정 항목을 선택하는지를 계속 말해주세요. 막히더라도 바로 도와드리지 않을 수 있습니다. 실제 데이터는 저장되거나 Apple에 제출되지 않습니다.

## 5. 과업 시나리오

### T1. 새 프로젝트와 공간 구조 준비하기

- 시작: [HOME-01 최근 프로젝트](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-4)
- 상황: 전시장 건물의 새 실내 지도 프로젝트를 맡았다. 주소를 찾고 A동의 1층과 2층 도면을 등록할 수 있게 준비하라.
- 참가자에게 말할 목표: “평면도를 등록할 수 있는 상태까지 프로젝트 구조를 준비해 주세요.”
- 관찰: 첫 행동, 새 프로젝트/기존 프로젝트 구분, 자동 제안 이름 이해, 주소 확인, 공간 계층 이해, Skip 기대
- 성공: 새 프로젝트로 진입하고 주소·프로젝트 이름·A동·1층·2층을 직접 추가한 뒤 [새 프로젝트 평면도 허브](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=140-139)에 도달
- 권장 제한: 8분

### T2. 1층 평면도 등록과 정렬

- 시작: [FLOOR-01P 새 프로젝트 평면도 허브](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=140-139)
- 상황: A동 1층 PDF 평면도가 준비되어 있다. 올바른 페이지를 선택하고 Apple 지도와 맞춰라.
- 참가자에게 말할 목표: “A동 1층 평면도를 등록하고, 지도와 정렬이 완료된 상태로 만들어 주세요.”
- 관찰: Building·Level 확인, PDF 페이지 선택, 수동/기준점 정렬 선택, 완료 판단
- 성공: 1층에 올바른 도면을 연결하고 Alignment Result를 적용
- 권장 제한: 6분

### T3. 공간과 출입구 작성 · 독립 상태 3개

- 이 과업은 Prototype의 선행 상태가 답을 노출하지 않도록 T3A~C를 독립적으로 연다. 상태 전환 시간은 과업 시간에서 제외한다.
- 상황: 1층 중앙 홀 옆에 새 실내 공간과 그 경계에 출입구를 작성해야 한다.
- 참가자에게 말할 목표: “중앙 홀 옆에 새 공간을 만들고, 중앙 홀로 통하는 출입구까지 작성해 주세요.”
- T3A 시작: [AUTHOR-01 Feature 선택기](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-19). 성공: Unit 선택 → 닫힌 Polygon 작성 → 연속 작성 종료 → 속성 저장 → Feature 선택기로 복귀.
- T3B 시작: [AUTHOR-01 Feature 선택기](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-19), Unit 12는 사전 조건으로 제공. 성공: Opening 선택 → LineString 작성 → 속성 저장 → 경계 확인 → [Opening 저장 완료](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=138-2).
- T3C 시작: [AUTHOR-13 Opening 경계 오류](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=93-5). 성공: 왜 유효하지 않은지 설명하고 `위치 다시 선택`으로 경계 확인 화면에 복귀.
- 관찰: Feature 종류 선택, Polygon/LineString 차이, Inspector 사용, 경계 연결 판단
- 주의: 이 과업에서 Unit–Opening 연결을 IMDF `relationship` Feature로 부르거나 생성하게 하지 않는다. `relationship`은 층간 이동 등 별도의 이동 연결 Feature다.
- 권장 제한: 10분

### T4. Geometry 오류 수정과 재검사

- 시작: [REVIEW-01 문제 요약](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-25)
- 상황: 프로젝트에 여러 문제가 발견되었다. 우선 처리할 문제를 선택해 원인을 확인하고 직접 수정한 뒤 검사하라.
- 참가자에게 말할 목표: “가장 먼저 처리해야 한다고 판단한 문제를 해결하고, 현재 남은 문제가 무엇인지 확인해 주세요.”
- 관찰: 문제 목록 우선순위, 지도 위치와 설명, 검토/편집 모드 구분, 재검사 결과, 목록 복귀 기대
- 성공: 문제 위치 확인 → 수정 시작 → Geometry 수정 → 재검사 → 해결 배너와 남은 문제 인지
- 권장 제한: 7분

### T5. 내보내기 상태별 판단

- 시작: [EXPORT-01 내보내기 허브](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-31)
- 이 과업은 하나의 연속 흐름으로 진행하지 않는다. 진행자가 각 상태의 시작 화면을 별도로 열어 이전 결과가 다음 판단을 암시하지 않게 한다.
- T5A 오류 상태: 제출용 ZIP을 시도한다. 성공은 ZIP 생성이 차단되고 문제 목록으로 이동하는 것.
- T5B 경고만 있는 상태: 제출용 ZIP을 시도한다. 성공은 경고를 확인한 뒤 계속하거나 취소하는 선택을 이해하는 것.
- T5C 검토용 ZIP: 클라이언트에게 보낼 검토 파일을 만든다. 성공은 오류와 무관하게 검토용임을 인지하고, 제출용 성공 화면으로 이동하지 않는 것.
- T5D ZIP 생성 실패: 실패 후 다시 시도하거나 다른 위치에 저장하는 복구 행동을 선택한다.
- 직접 시작 링크와 종료 증거:
  - [T5A EXPORT-03 제출 차단](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=89-2) → 문제 보기 또는 검토용 선택
  - [T5B EXPORT-04 경고 확인](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=89-3) → 제출용 ZIP 생성 진행
  - [T5C EXPORT-05 검토용 확인](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=89-4) → [검토용 완료](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=131-119)
  - [T5D EXPORT-08 ZIP 실패](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=89-5) → 재시도 또는 내보내기 허브
- 진행자는 각 하위 과업 전에 해당 링크를 새로 열고 타이머를 시작한다. 이전 하위 과업의 화면·발언은 초기 상태로 간주하지 않는다.
- 공통 질문: “이 파일이 Apple IMDF Validator를 통과했다고 말할 수 있나요?” 정답은 아니다. 앱의 Preflight와 외부 Validator 확인은 구분된다.
- 관찰: 검토용/제출용 구분, 오류 차단 이해, 경고 확인, 실패 복구, Apple Validator 인식
- 권장 제한: 10분

### T6. 도면 교체 후 안전하게 작업 계속하기

- 시작: [FLOOR-07 도면 관리·교체 시작](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=131-160). FLOOR-08은 참가자의 선택 이후에만 제시한다.
- 상황: 납품 후 1층 평면도가 변경되었다. 기존 Geometry를 잃지 않고 새 도면으로 교체해야 한다.
- 참가자에게 말할 목표: “기존 작업을 보존하면서 새 도면으로 교체하고, 다음에 무엇을 검토해야 하는지 확인해 주세요.”
- 관찰: 기존 Geometry 유지 기대, 지도 좌표 고정 이해, 검토 필요 상태, 재검사 경로
- 성공: 교체 영향 예측을 먼저 말함 → 기존 Geometry 유지 확인 → 새 도면 교체 → 재정렬 → Review Required → 영향받은 Feature 검토 화면 도달
- 권장 제한: 5분

## 6. 힌트 규칙

| 단계 | 조건 | 진행자 문구 | 판정 |
|---|---|---|---|
| H0 | 스스로 진행 | 말하지 않음 | 독립 성공 |
| Probe | 행동 직후 | “무엇을 기대하고 선택했나요?” | 탐색 질문, 힌트 아님 |
| H1 | 한 의사결정 지점에서 60초 정체 | “지금 찾고 있는 것은 무엇인가요?” | 중립 질문, 독립 유지 |
| H2 | 같은 지점에서 90초 정체 | “화면에서 현재 단계와 관련된 영역을 찾아보세요.” | 약한 힌트 |
| H3 | 같은 지점에서 120초 정체 | 관련 패널 또는 영역을 지목 | 강한 힌트 |
| 중단 | 3분 정체 또는 반복 오류 | 다음 상태로 이동 | 실패 |

버튼 이름이나 정답 경로를 직접 말하면 H3로 기록한다.

## 7. 과업 판정 기준

| 점수 | 의미 |
|---:|---|
| 2 | 힌트 없이 목표 완료 |
| 1 | H2 또는 H3 이후 완료 |
| 0 | 목표 미완료, 잘못된 결과, 진행자 대행 |

Critical Error는 과업 점수와 별도로 기록한다.

- 잘못된 Building·Level에 Feature 작성
- Unit 경계 밖에 놓인 Opening을 유효하다고 판단
- 경고·오류가 있는 제출용 ZIP을 문제없이 제출 가능하다고 판단
- 앱 내부 검사를 Apple IMDF Validator 통과로 이해
- 취소 후 변경된 Geometry가 남아 있거나, 교체·복원 후 기존 Geometry가 실제로 사라진 상태를 완료로 수용함

## 8. Round 1 통과 기준

| 지표 | 통과 기준 |
|---|---:|
| T2~T5 독립 성공률 | 각 과업 80% 이상 |
| 전체 과업 완료율 | 85% 이상 |
| Critical Error | 동일 유형 0~1명 |
| 과업 후 난이도 SEQ | 중앙값 5/7 이상 |
| 90초 이상 무행동 | 전체 과업의 10% 미만 |
| Preflight와 Apple Validator 혼동 | 0명 |

참가자 2명 이상이 같은 지점에서 H2 이상을 필요로 하면 화면 문제로 분류한다. 한 명의 취향이나 용어 선호는 즉시 설계 변경하지 않고 패턴을 확인한다.

## 9. 사전·사후 질문

### 사전 질문

1. IMDF 파일을 얼마나 자주 만들거나 검토하는가?
2. 현재 어떤 도구와 파일 형식을 사용하는가?
3. 가장 어렵거나 실수가 잦은 작업은 무엇인가?
4. Apple IMDF Validator는 언제, 어떻게 사용하는가?

### 과업 후 공통 질문

1. 이 과업은 얼마나 쉬웠는가? 1~7점으로 답해달라.
2. 다음 화면에서 어떤 결과를 기대했는가?
3. 확신이 없었던 순간은 어디였는가?

### 세션 종료 질문

1. 가장 신뢰할 수 있었던 부분과 가장 불안했던 부분은 무엇인가?
2. 앱이 막아줘야 한다고 느낀 실수는 무엇인가?
3. 설명이 너무 많거나 부족했던 곳은 어디인가?
4. 기존 도구와 비교해 더 빠를 것 같은 작업과 느릴 것 같은 작업은 무엇인가?

## 10. 이 테스트에서 확인하지 않는 것

- 최종 색상·Typography·브랜드 완성도
- Apple Pencil의 실제 그리기 정밀도와 성능
- 실제 MapKit 주소 검색·지도 타일·오프라인 캐시
- 실제 IMDF Schema 직렬화와 Apple Validator 결과
- iCloud의 실제 동기화와 충돌 처리
- VoiceOver, Dynamic Type, 키보드 조작의 구현 품질

이 항목들은 Lo-Fi가 아니라 구현 Prototype과 기능 테스트 단계에서 검증한다.

## 11. 결과 처리

각 발견 사항은 다음 형식으로 기록한다.

```text
UT-01 · [심각도] · [Screen ID]
관찰: 사용자가 실제로 한 행동
영향: 과업 실패, 지연, 오해, 신뢰 저하 중 하나
근거: 참가자 수와 발언·행동
권고: 화면, 문구, 순서, 규칙 중 무엇을 변경할지
연결: 관련 Decision ID
```

심각도:

- S0: 데이터 손실·잘못된 제출 가능성, 즉시 수정
- S1: 핵심 과업 실패 또는 반복 정체, 다음 테스트 전 수정
- S2: 우회 가능하지만 이해·효율 저하, 우선순위 판단
- S3: 선호나 미세 표현, 시각 디자인 단계에서 검토
