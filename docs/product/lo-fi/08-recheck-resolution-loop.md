# 재검사 후 문제 해결 루프 Deep Dive

상태: Lo-Fi 5상태 제작·연결·검증 완료

작성일: 2026-08-25

Figma: [Lo-Fi · 31 Screen Flow](https://www.figma.com/design/kqT9zmJTq9nOoV43y6hYqS?node-id=51-2)

## 목적

Geometry 수정 후 재검사 결과가 단순한 성공 화면에서 끝나지 않고, 남은 문제 선택·위치 확인·수정 취소·앱 내 오류 0 상태까지 닫힌 루프로 이어지는지 검증한다.

## 상태 정의

### REVIEW-06A · 수정 성공·다른 문제 존재

- 방금 해결된 `Unit 12`를 화면 최상단 성공 배너에서 강조한다.
- `프로젝트에 다른 오류 2개가 남아 있습니다`로 현재 상태를 함께 알린다.
- 해결된 문제는 남은 문제 목록에서 제거한다.
- 오류·경고·미완료 개수를 즉시 갱신한다.
- Primary Action은 `전체 문제 보기`다.

### REVIEW-06B · 전체 문제 목록

- 오류 → 경고 → 미완료 순으로 묶는다.
- 같은 상태 안에서는 건물 → 층 순으로 정렬한다.
- 각 행은 `Feature · 건물 층`과 쉬운 문제 설명의 두 줄로 구성한다.
- 사용자가 다음 문제를 직접 선택하며 자동으로 다음 오류를 열지 않는다.
- 다른 화면에서 돌아오면 스크롤, 필터, 건물·층 펼침 상태와 정렬을 유지한다.

### REVIEW-04B · 문제 위치·설명

- 지도는 문제가 발생한 위치로 이동한다.
- Inspector는 원인과 수정 방법을 함께 표시한다.
- 처음에는 검토 모드이며 편집을 자동 시작하지 않는다.
- Primary Action은 `수정 시작`, Secondary Action은 `전체 문제 보기`다.
- 같은 오류가 재검사 후에도 존재할 때 이 화면을 재사용한다.
- `다시`, `여전히`, `아직` 대신 `검사 완료 · 오류 1개`처럼 현재 결과만 표시한다.

### AUTHOR-06D · 변경 사항 버리기

- 편집 중 `변경 취소`를 누를 때만 확인창을 표시한다.
- `계속 수정`은 편집 상태로 돌아간다.
- `변경 사항 버리기`는 편집 전 Geometry를 복원하고 같은 문제 위치·설명 화면으로 돌아간다.

### REVIEW-06C · 앱 내 오류 0

- 제목은 `앱 내 사전 검사에서 오류가 발견되지 않았습니다`다.
- 오류·경고·미완료 개수를 함께 표시한다.
- Apple IMDF Validator 확인은 내보내기 후 별도로 필요함을 명시한다.
- Primary Action은 `내보내기 준비 확인`, Secondary Action은 `프로젝트로 돌아가기`다.
- Apple 제출 준비 완료나 Validator 통과를 주장하지 않는다.

## Prototype 연결

```text
REVIEW-05 재검사
→ REVIEW-06A 수정 성공·다른 문제 존재
→ REVIEW-06B 전체 문제 목록
→ REVIEW-04B 문제 위치·설명
→ AUTHOR-06A 문제 진입
→ AUTHOR-06B 수정 중
→ AUTHOR-06C 유효성 통과
→ REVIEW-05 재검사
```

취소 분기:

```text
AUTHOR-06B 또는 AUTHOR-06C
→ AUTHOR-06D 변경 사항 버리기
  ├─ 계속 수정 → AUTHOR-06B
  └─ 변경 사항 버리기 → REVIEW-04B
```

완료 분기:

```text
REVIEW-05 재검사
→ REVIEW-06C 앱 내 오류 0
→ EXPORT-01 내보내기 준비 확인
```

Figma의 단순 클릭 프로토타입은 데이터 조건에 따른 자동 분기를 지원하지 않으므로 `REVIEW-06A`와 `REVIEW-06C`를 서로 다른 결과 예시로 둔다.

| 검사 항목 | 결과 |
|---|---:|
| 신규 Deep Dive 화면 | 5개 |
