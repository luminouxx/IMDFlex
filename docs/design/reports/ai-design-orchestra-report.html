수행한 일

  • Figma와 Apple Schema의 책임 분리
  • Preflight와 Validator의 역할 분리

미확인

사용자 결정

SE

SwiftUI Architecture Team

Figma-to-code 계약과 구현 가능성

 조건부 완료Minor 3

이번 목표

승인된 Figma 명세가 SwiftUI와 Clean Architecture로 안전하게 이관되도록 한다.

수행한 일

  • Figma, SwiftUI, Domain의 Source of Truth 분리
  • Token과 Swift enum의 기계적 매핑 제안
  • GitHub Issue, Branch, PR 전달 계약 정의

핵심 발견

Material과 직접 opacity, 하드코딩 수치는 Figma와 코드의 일치를 어렵게 하므로 semantic token으로 이동해야 합니다.

위험

코드 구현을 Foundations 승인 전에 시작하면 현재 DesignSystem API와 새 Token 체계가 동시에 변해 재작업이 커집니다.

다음 작업

Component API가 안정된 뒤 Issue를 분할하고 기존 API를 alias하는 단계적 이관안을 작성합니다.

QA

Independent Critic

역할 중복, 승인 피로와 컨텍스트 드리프트

 완료Major 3

이번 목표

오케스트라 자체가 복잡성과 랜덤한 결과를 만드는 위험을 검토한다.

수행한 일

  • 산출물 단독 소유권 규칙 제안
  • Project Constitution과 Decision Log 제안
  • 승인 Gate와 Stop Condition 검토

핵심 발견

여러 시안을 섞기 전에 평가 기준을 고정하지 않으면 눈에 띄는 결과가 제품 원칙보다 우선될 수 있습니다.

위험

  • 같은 산출물을 여러 Agent가 소유하면 충돌 발생
  • 모든 세부사항을 사용자에게 묻으면 승인 피로 발생
  • 결정이 대화 기록에만 있으면 다음 Phase에서 맥락 유실
